01 / Framework

先用这张总图建立框架：从价格变化开始，沿着仓位、强平、穿仓、基金与 ADL 一路向下。后面的章节只负责放大其中一段。

先由仓位与账户承担，再向公共资金传递，最后才触及盈利方。 规则样本：币安官方公开说明
澄清 01

“99% 都靠卖资产”

方向合理，但没有找到官方统计能证明 99%。更准确的说法是：多数合约风险由保证金和强制减仓处理，信用追偿不是主路径。

澄清 02

保险基金不是保险

币安明确说明它不保证用户收益，也不会把已经发生的客户交易亏损退还。它只处理穿仓造成的对手方缺口。

澄清 03

ADL 不是“所有人一起亏”

ADL 先选反向、盈利、有效杠杆较高的仓位。它是定向自动减仓，不是平均分摊给全市场。

02 / Definitions

先分清四件事

“清算”常被口语化使用。把它拆成账户亏损、强制卖出、穿仓、自动减仓，因果关系会更清楚。

清算不是一种单一动作，而是一串兜底顺序

传统市场把这一步叫 default waterfall。币圈合约交易所也采用类似的“瀑布”：客户权益先吸收亏损，随后是强平成交、保险基金，最后才轮到 ADL。每一步只处理上一步没有覆盖的缺口。

!

“匿名所以无法追偿”是现实因素之一，但更关键的结构是：合约仓位通常已经被保证金预先约束。系统不需要先相信客户未来会还钱，而是先拿账户资产抵亏。

01 / PNL 市场亏损

仓位价格变化造成的损失，先由账户保证金承担。此时还可能只是浮亏，并未被强制平仓。

02 / LIQUIDATION 强制清算

保证金不足时，风险引擎取消挂单并强制减仓或平仓，把风险敞口卖掉。

03 / BANKRUPT 穿仓

把客户可用资产和仓位处理后，余额仍小于 0，或仓位无法在市场平掉。

04 / ADL 自动减仓

保险基金也接不住时，系统按优先级自动平掉部分盈利方的反向仓位。

03 / Binance public rules

币安合约：一笔亏损如何被处理

以下内容以币安在 2026 年 1 月更新的官方说明为核验样本。规则可能调整，交易前应重新查看原文。

A / 触发与计算

强平按“标记价格”触发

币安官方原文明确：仓位的清算价格和未实现盈亏按 Mark Price 计算。系统在 Mark Price 触达清算价格时触发清算。用户看到的强平价与实际成交价可能不同。

可用权益 = 初始保证金 + 已实现盈亏 + 未实现盈亏
当 可用权益 < 维持保证金，进入清算。
注意：剧烈波动可能让 Mark Price 一跳越过清算线，实际成交比预设强平价更差。
B / 触发后发生什么
  • 1先取消挂单。全仓模式取消全账户挂单；逐仓模式取消同一币种仓位的挂单。
  • 2发一笔大型 IOC 单。系统尝试把仓位尽量卖向市场；成交多少算多少，剩余部分立即取消。
  • 3检查缺口。成交后如果客户权益仍足够覆盖维持保证金，清算停止。
  • 4剩余仓位变成穿仓仓位。保险基金在能力范围内接管；损失由基金承担，盈利也归基金。
“甩单”与账户处理：公开规则能确认到哪里 source: Binance Liquidation Protocols
Origin 从客户仓位发出

强平单先减少客户仓位，不是一开始就把整个账户原样搬给保险基金。

Execution 一笔大型 IOC

官方只写明“一笔大型立即成交或取消单”，没有公开固定分层数量或单笔上限。

Residual 剩余部分变穿仓

IOC 未成交部分被取消后，交由风险引擎和保险基金处理。

Takeover 基金接管仓位

基金按破产价格接管，承担后续亏损；不是对客户交易亏损进行报销。

✓

关于“分层甩单”的结论：币安公开文件描述的是单笔大型 IOC，而不是公开写明的固定多层分批。可能在底层风险系统里有更细的执行控制，但没有公开一手材料，不应把“分几层、每层多少”当作已知事实。

04 / Insurance fund

保险基金：池子不是“每个合约一个”

币安按合约类别维护多个基金，每个基金可能分布在多个钱包中。不同 USDT 合约不一定共享同一个池。

What it actually does
补差额不是存款保险，也不退还客户交易亏损

基金只在保险基金接管“穿仓仓位”时，承担破产价格与清算成交之间的差额。基金来自清算费的一部分、交易所补充资金，以及接管仓位后可能产生的盈利。

基金会设置“最大接管容量”，定义为基金余额的某个倍数；倍数因风险管理原因不公开。达到上限后，风险引擎不能再继续吃下穿仓仓位，ADL 才会被触发。官方用 99.9% 置信区间和历史极端情景校准最低基金规模，但这不代表 99.9% 的清算都不会触发 ADL。币安也可能调整合约所属基金组，因此交易前应看官网当前分组，而不是记死一张旧表。

05 / Auto-deleveraging

ADL：从盈利方反向平仓

它是最后防线，不是日常强平。系统需要找方向相反的盈利仓位，优先自动减掉“盈利更多、杠杆更高”的仓位。

排名公式 / Binance public formula

先算盈利比例，再乘或除有效杠杆

STEP 1 盈亏比例 = 未实现盈亏 / |仓位名义价值|
STEP 2 有效杠杆 = |仓位名义价值| / (账户余额 + 未实现盈亏)
STEP 3 若盈亏比例 ≥ 0：排名值 = 盈亏比例 × 有效杠杆
STEP 4 若盈亏比例 < 0：排名值 = 盈亏比例 / 有效杠杆
STEP 5 ADL Quantile = 用户排名 / 用户总数

组合保证金模式下，有效杠杆按账户权益计算：|仓位名义价值| / accountEquity。

Priority reading

越靠前，越先被自动平仓

盈利比例和有效杠杆共同决定排序。界面上的 ADL 指示灯对应仓位在队列中的分位；灯越满，被自动减仓的概率越高。Delta Neutral 账户达到阈值时，其已对冲仓位会排在更后。

低概率高概率

执行价格：盈利方仓位按亏损方的破产价格关闭。

交易费用：官方说明，被 ADL 的盈利方不收取交易费。

通知与结果：系统通知被平仓数量与价格；盈利可能被部分减少或全部抹平。

06 / Spot boundary

现货为什么通常没有这套 ADL 瀑布？

普通现货是一手交钱、一手交货。真正需要“卖出资产还债”的场景，通常来自现货借贷、杠杆或平台自身风险。

Plain-language boundary

普通现货：交易完成，信用关系结束

买方先有资产才买入，卖方成交后交付资产。只要平台完成账本结算，双方没有持续的保证金义务，也就不需要保险基金去补一个“合约对手利润”。

普通现货没有杠杆，就没有强制平仓瀑布。
现货杠杆 / 借贷借来的钱或币需要偿还，抵押物下跌时会自动卖出。
平台破产或挪用属于信用、托管和偿付能力问题，不是 ADL 能解决的交易风险。
